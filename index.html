🎙️ Presenter: Member 1 (Lead & UI Architect)

The Problem: What is a "Silent Failure"?

In enterprise operations, data files often look completely healthy on the surface, but contain critical corruptions inside.

Traditional Schema Checkers (Blind Spot)

Conventional validators only check syntax:

  • Are headers present? Yes.
  • Is encoding valid UTF-8? Yes.
  • Does CSV parse without crashing? Yes.
⚠️ Result: File passes with HTTP 200 OK — silently poisoning databases and operational reports.
SilentGuard Semantic Validation

SilentGuard verifies actual business integrity:

  • Salary: -$5,000 — valid number, but financially impossible.
  • Dispatch < Manufacturing Date — chronological flaw.
  • Supplier Code 'UNKNOWN' — breaks ERP lookup.
  • Duplicate IDs — causes erroneous payroll transfers.
✅ Result: 100% deterministic detection and cell-level error flagging before ingest.

Tier 2: Dynamic Database Tier
🎙️ Presenter: Member 5 (Dynamic DB & Streaming)

Dynamic PostgreSQL DDL & SQL Injection Defense

Automating schema provisioning for every uploaded CSV without database crashes or security vulnerabilities.

1. Dynamic Staging Table Provisioning

For every file uploaded, CsvImportService generates an isolated PostgreSQL table via JdbcTemplate:

CREATE TABLE IF NOT EXISTS ds_motherson_parts_17145892 (
    _row_id SERIAL PRIMARY KEY,
    "batch_id" TEXT,
    "part_number" TEXT,
    "dispatch_date" TEXT,
    "quantity" TEXT
);
  • Why TEXT Columns? Malformed strings (e.g. "PENDING" in quantity) are safely stored without aborting the ingest.
  • Zero Inter-Dataset Collisions: Independent tables isolate datasets cleanly.
2. SQL Injection Defense & Whitelisting

Strict header sanitization eliminates malicious SQL vectors:

// Regex Whitelist: only alphanumeric + underscores
String cleanHeader = raw.replaceAll("[^a-zA-Z0-9_]", "_");

// Parameterized JDBC Batch Binding
String sql = "INSERT INTO " + tableName + " VALUES (?, ?, ?)";
jdbcTemplate.batchUpdate(sql, pss);
  • No String Interpolation: Parameter binding prevents SQL injection.
  • High Throughput: Commits 5,000+ rows per JDBC round-trip.

Tier 3: Rule Intelligence Engine
🎙️ Presenter: Member 4 (Validation Algorithms)

Deterministic Rule Engine: 8 Business Processors

100% deterministic quality evaluations executed against dataset cells, composite keys, and cross-column logic.

1. REQUIRED
Catches empty, null, or whitespace-only dummy cells ("N/A").
2. UNIQUENESS
O(1) frequency map catching duplicate primary & composite keys.
3. MIN / MAX RANGE
Parses numbers safely and flags boundary violations (e.g. salary < 0).
4. FORMAT / REGEX
Validates pattern compliance (RFC 5322 emails, ISO dates, Part SKUs).
5. CROSS-FIELD
Chronological checks (e.g. dispatch_date >= mfg_date).
6. REFERENTIAL
Verifies foreign keys against approved enterprise catalog lists.
7. SCHEMA DRIFT
Alerts if incoming CSVs are missing expected business columns.
8. CHECK CONSTRAINT
Validates multi-valued delimited lists against allowable values.
Tier 3: Health Scoring Model
🎙️ Presenter: Member 4 (Validation Algorithms)

Graduated Continuous Health Score Algorithm

Replacing fragile binary scoring with a balanced mathematical model that penalizes defect density realistically.

Mathematical Scoring Formula
PassRatio = PassedRecords / TotalRecords

WeightedDefects = (Critical * 2.5) + (Error * 1.0) + (Warning * 0.2)

DefectDensity = WeightedDefects / TotalRecords

DensityDeduction = min(30.0, DefectDensity * 20.0)

HealthScore = round(PassRatio * (100.0 - DensityDeduction))

Score is clamped between 0% and 100%, preventing sudden catastrophic score drops for datasets with isolated issues.

Severity Hierarchy & Parity
SeverityWeightAction
CRITICAL2.5×Quarantine record (Negative Salary, Drift)
ERROR1.0×Flag cell (Invalid Email, Unknown Code)
WARNING0.2×Notify steward (Whitespace, casing)
✅ 100% Client-Server Parity: Java backend and TypeScript frontend compute identical scores.
